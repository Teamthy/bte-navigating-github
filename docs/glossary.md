# Glossary

**Branch** — a parallel line of development so you can work without touching `main`.

**Clone** — downloading a copy of a repository to your computer.

**Commit** — a saved snapshot of staged changes, with a message.

**CONTRIBUTING.md** — a file in a repo explaining how outside contributors should submit changes.

**Fork** — your own copy of someone else's repository, under your GitHub account.

**Issue** — a tracked task, bug, or discussion on a GitHub repository.

**Label** — a tag on an issue or PR (e.g. `good first issue`, `bug`) used to categorize it.

**main** — the default, primary branch of a repository (formerly often called `master`).

**Merge** — combining changes from one branch into another.

**Merge conflict** — when Git can't automatically combine changes because the same lines were edited differently on two branches. See [`merge-conflicts-explained.md`](merge-conflicts-explained.md).

**origin** — the default name Git gives to the remote you cloned from (usually your fork).

**Pull request (PR)** — a request to merge your branch's changes into another branch, opened on GitHub, usually reviewed before merging.

**Push** — uploading your local commits to a remote repository.

**Remote** — a version of your repository hosted elsewhere (e.g. on GitHub).

**Repository (repo)** — a project tracked by Git, including all its files and history.

**Staging area** — the holding zone where you select which changes go into your next commit.

**upstream** — the convention for naming the remote pointing to the original project (not your fork).

**Working directory** — the files on your computer as you're currently editing them.
