# Drill 10: Writing a Good PR Description (no commands, no code)

Applies Section 03, Topic 5. A bad PR description is one of the most common reasons a maintainer ignores a PR.

## Task

Below is a real bad PR description. Rewrite it in `rewrite.md` so it explains what changed, why, and links the issue.

> "fixed it"

Your rewrite should include: what was fixed, which file(s), and `Closes #<issue-number>` (invent a plausible issue number).
